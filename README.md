# Block2Script プロンプトメーカー

中学校の技術科「計測・制御」の授業で、使う装置・接続端子・AIのClass・動作条件を整理し、Block2Script専用Gemへ渡す指示文をつくる静的Webアプリです。GemそのものやB2Sコードは生成しません。

## 使い方

1. 作りたい作品の目的を書く。「猫の給水サンプルを読み込む」から始めてもOK。
2. **S：センサ**を追加し、外付けなら信号端子を選ぶ。
3. **A：アクチュエータ**を追加し、接続を入力する。同種も複数追加・個別削除可能。
4. AIを使うなら種類を選び、Class名を**1行1つ、学習時と同じ文字**で入力する。モデルURLは任意。
5. 「どんなときに、何を動かし、いつ止め、次にいつ動くか」を書く。
6. 「指示文をつくる」で確認する。指示文は編集してコピーできる。専用Gemへ貼り付け、生成されたコードをBlock2Scriptで試す。

サンプルは重量センサ、デジタルマイクロポンプ、画像分類のC1/C2/D1/D2/noneを設定します。重量１０ｇ以下・C1の場合のみ給水、連続給水を防ぐという条件を含めます。**ポンプの端子は未選択**です。実物に合わせて入力するまで生成できません。専用プログラム、通信ラベル、停止・再動作条件は未確認としてGemに質問を求めます。

## デザイン

「発明ワークショップ」として、左の作業メニュー、中央の装置選択・設定、右の発明セットの3領域を使います。メニューで6つの作業パネルを切り替えるため、画面全体を長くスクロールして入力箇所を探す必要はありません。Sは青緑、Aはオレンジ、AIは紫で分離しています。

画像カードから装置を追加すると右の装備欄へ即時反映され、端子・未設定・確認事項を見ながら個別に編集できます。同じ装置も複数追加できます。狭い画面では装備欄を開閉でき、スマートフォンでは1カラムで操作できます。動きを減らすOS設定にも対応しています。

画面設計・検証は [`docs/workshop-ui.md`](docs/workshop-ui.md)、画像19点の出典・ライセンスは [`docs/visual-ui.md`](docs/visual-ui.md) を参照してください。画像はすべてサイト内から配信します。

## Gemへのお願いのしかた

最終ステップで「AIにおまかせ」（初期設定）と「自分で細かく決める」を選べます。おまかせでは安全な演出の初期値をAIが採用してコード作成を優先し、詳細モードでは未指定の条件を確認します。どちらも接続・実際のモデルURL・Class名・安全上重要な条件は推測させません。変数・リストは「Scratchへ反映」で自動作成する前提です。

内蔵装置は同じIDを1回だけ選択できます。旧保存にある重複は自動削除せず、装備欄で整理を案内します。モード・保存互換性・[改善前後の防犯模型のプロンプト例](docs/gem-guidance.md)も参照してください。

## 保存・プライバシー

入力、接続、AI設定、編集後の指示文を、このサイト・このブラウザのlocalStorageへ自動保存します。再読み込みすると復元します。外部サーバー、生成AI API、解析サービス、CDN、外部フォントは使いません。生徒の入力は外部送信しません。装置ガイドなどの外部リンクは、生徒が開く場合だけ移動します。

共有端末では「入力を消す」を押してください。端末・ブラウザ・URLが変わると保存内容は引き継ぎません。保存禁止・容量不足なら画面に知らせます。保存は無期限に残る場合があり、ブラウザ側で消すこともできます。「一時保存」は授業用の下書き保存であり、自動消去の意味ではありません。

接続や動作を変えると生成済み指示文を古いものと表示し、再生成するまでコピーを止めます。モデルURL・Classも外部へ取得・検証しません。コピーが許可されないときは本文を選択して手動コピーを案内します。

## 装置情報と確認事項

設定データは [`data/devices.js`](data/devices.js) で独立管理しています。装置ID・表示名・S/A・内蔵区分・接続方式・役割別フィールド・許可端子・共有方式・対応状況を持ちます。必要端子数はpin/fixedのフィールド数から決まります。

装置の追加時には教材掲載とB2S命令・配線仕様の両方を確認してください。MakeCodeだけの対応をB2S対応済みとはしません。詳細・参照commit・未確認項目は [`docs/device-support.md`](docs/device-support.md) にまとめています。Microbit More、TM2Scratch、実機のファームウェアが実際に読み込まれているかは、GemとBlock2Script側で確認する必要があります。

## ローカル起動

ローカル起動にはNode.js 22以降を使います。アプリ本体にはインストールやビルドは不要です。

```sh
npm run dev
# http://localhost:5180 を開く
```

`file://`でHTMLを直接開くと、JavaScriptモジュールや保存が制限されることがあるため、HTTPサーバーを使ってください。

## テスト

```sh
npm test                         # 依存なしのロジックテスト18件
npm ci                           # 開発用Playwrightのみ
npx playwright install chromium
BROWSER_PATH=/path/to/chromium npm run test:browser
# 別ターミナルで npm run dev を起動しておく
```

`PORT=5181 BASE_PATH=/block2script-prompt-builder/ npm run dev` でサブディレクトリ配信を試せます。

`BROWSER_PATH`で実行ブラウザーを指定できます。未指定ならLinuxの`/usr/bin/chromium`があれば使い、なければPlaywrightがインストールしたChromiumを使います。`TEST_URL`で試験先を変えられます。ブラウザーテストは表示・入力・コピー・保存復元・Class保持・端子重複・破損／禁止ストレージ・外部送信がないことを確認します。スクリーンショットはgit対象外の`work/`へ保存します。実機の接続試験・Gemの回答品質は今回のテスト範囲に含みません。

## GitHub Pagesで公開する

1. このリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。
2. `main`へpushするか、Actionsの **Test and publish prompt maker → Run workflow** を実行する。
3. ロジックテストとサブディレクトリのブラウザーテスト成功後、必要な静的ファイルだけを `_site` に集め、GitHub Pagesへ公開する。
4. 公開先：<https://playa2021git.github.io/block2script-prompt-builder/>

すべてのアセット・モジュールを相対パスで参照するため、`/block2script-prompt-builder/`のサブディレクトリで配信できます。独自サーバーやAPIキー、データベースは不要です。公開先で設定変更が必要な場合はリポジトリ管理者がPagesを有効化してください。

Actionsを使わず公開する場合は、PagesでDeploy from a branch → main / (root)を選んでも動作します（`.nojekyll`同梱）。その場合はActionsワークフローを無効化し、公開方式を混在させないでください。
