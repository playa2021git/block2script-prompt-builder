# Gem連携と装置選択の改善

3カラムの発明ワークショップ、画像、装置ID・接続仕様は維持しています。

## 生徒の操作

- 同じ内蔵装置は新たに重複追加せず、選択済みカードへフォーカスして強調します。カード選択・名前の一覧・キーボードのいずれも同じ処理を使います。外付け装置は複数追加できます。
- 旧保存データにある内蔵装置の重複は削除しません。各カードに「内蔵装置が重複」と整理方法を表示し、生徒が不要な登録を外せます。
- 最終ステップで「AIにおまかせ」（初期設定）と「自分で細かく決める」を選びます。切り替えると以前の生成文を古いものとして扱い、再生成するまでコピーを止めます。
- 装備欄では「設定完了」「入力が必要」「端子が競合」「内蔵装置が重複」「B2S対応要確認」「配線・電源の実機確認」を分けます。端子競合は両方の装置に表示し、編集すべき端子をメッセージで示します。I2Cアドレスの競合は端子競合と区別します。
- モデルURLが空欄でも指示文は生成できますが、装備欄では入力が必要な事項として表示し、認識の実行に必要なら実際の共有URLを確認するようGemへ伝えます。

## 生成方式

おまかせでは、既に指定された内容を保持し、音の高さ・表示・演出の待機時間など危険のない調整値はAIが初期値を採用し、短く説明します。質問は実現に不可欠な不足情報に絞ります。

端子、実際のモデルURL、Class名、配線、電源、安全上重要な条件は両モードとも推測禁止。ポンプ・モータ・鍵の制御では停止、連続動作防止、異常時の扱いを検討し、安全性を確認できない部分は模型・シミュレーション向けに限定します。実際の住宅の鍵を画像分類だけで自動解錠する設計にはしません。

詳細モードでは未指定の動作時間・しきい値・停止条件・再動作条件について必要な質問をコード作成前にまとめます。

変数・リストはコード内で参照し、B2Sの「Scratchへ反映」で自動作成する前提です。生徒へ手動作成を指示しません。汎用の対応説明を装置ごとに繰り返すのをやめ、接続情報・個別の重要事項・実機確認事項へ整理しました。

## 防犯模型の改善前後

ユーザー指定の構成を `tests/fixtures/security.mjs` に定義しています。明るさ30未満、人感P0、内蔵スピーカー、SG90 P1（0度/180度）、5×5 LED、画像認識のClass名「家の人」「クロネコヤマト」「怪しい人」、モデルURL未入力です。

実際の生成全文：

- [改善前](prompt-examples/security-before.txt)：1,518文字。基準commit `8a3301b` の生成処理で作成。
- [AIにおまかせ](prompt-examples/security-auto.txt)：1,432文字。
- [自分で細かく決める](prompt-examples/security-precise.txt)：1,252文字。

文字数は末尾に保存用として追加する改行を除いたものです。指定値・接続・Class名を残しながら、モード・安全方針・変数の自動作成を追加しています。

改善前の一律ルール：

> 記載のない装置・端子・Class名・動作時間・しきい値・再動作条件を推測で決めないでください。不足する情報があれば、コードの前に質問してください。

改善後のおまかせ：

> 原則として質問よりコード生成を優先してください。未指定の危険のない演出・効果音の高さ・画面表示・表示や演出の待機時間には合理的な初期値を提案・採用し、採用した値を短く説明してください。これらの調整値だけを理由に確認質問を並べないでください。

共通の変数・リスト方針：

> 必要な変数やリストはB2Sコード内で参照し、「Scratchへ反映」で自動作成される前提で生成してください。生徒に変数・リストを手動作成させないでください。

## 保存互換性

保存キーとversion 1を維持し、`promptMode` を追加しています。未指定・不正なモードは読み込み時におまかせへ戻します。配列の重複や装置のメモを勝手に削除しません。

旧モードなしの保存には、新しい方針と異なる旧生成文が含まれる可能性があります。その文は編集内容も含めて保持し、再生成が必要な状態にします。新モードで生成・編集した文章は、入力が一致していれば再読み込み後もそのままコピーできます。

## 検証・変更ファイル

- `npm test`：既存13件＋新規5件の計18件。モード別の方針、推測禁止、変数自動作成、防犯模型の値保持、旧保存移行、競合の分類を検証。
- `npm run test:browser`：既存の画像・ワークショップテストと、新しい `tests/gem-modes.test.mjs`。内蔵装置の再選択、旧重複データの保持・整理、外付けの複数追加、モード変更時の無効化、保存・復元、防犯模型の生成文との一致を検証。
- 通常配信とGitHub Pagesのサブディレクトリ配信で同じチェックを実行。
- スクリーンショット：git対象外 `work/gem-modes.png`。

主な変更は `core.js`（生成・保存互換性・検証の分類情報）、`app.js`（選択操作と状態表示）、`index.html`・`style.css`（2モードと表示）、`package.json`、テスト、説明資料です。装置データ・画像・依存関係・ロックファイルは変更していません。

Gemへ実際に送信して回答回数や生成コードを検証するテストは実施していません。ここで検証したのは、生成する指示文とブラウザの動作です。
