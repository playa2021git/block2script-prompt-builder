# 発明家の作業台：モーション配置・検証記録

## 調査と変更範囲

対象は `index.html` / `app.js` / `style.css` の静的サイト。6工程を1つずつ見せるウィザードで、スクロール型ではない。発明セットは幅900px以下で折りたたむ既存の構造。S/Aは既存の共通関数を維持し、演出も同じ `motion.added()` を使う。

追加ファイルは `motion.js` と `motion.css`。`core.js`、装置データ、既存の保存キー・JSON形式は変更していない。Motion PromptのCanvasコードを実行時取得する処理や、外部ライブラリ・外部画像・フォントは追加していない。データは従来どおり端末内に留まる。

参考：[Motion Prompt](https://showheyohtaki.github.io/motion-prompt/)、[SKILL.md](https://github.com/showheyohtaki/motion-prompt/blob/main/skills/motion-prompt/SKILL.md)。CLIのget/kitで仕様を確認し、DOMで動作する形へ再構成した。MIT、Copyright (c) 2026 Shohei Ohtaki。ソース冒頭とページ末尾にクレジットを記載した。以前の `docs/quiet-motion.md` の提案を今回の仕様で拡張している。

## 仕様との差分・適用しない項目

- #074・#079・スクロールスパイ本体：ウィザード型なので適用しない。現在工程の追跡で代替。
- #044：reduce時は不透明度アニメも加えず即時表示。全動作が止まる方を優先。
- #126のデスクトップ着地点が画面外：飛行を省略してその場で状態を伝える。モバイルは新設の下バーが着地点。存在しなかった下バーは新設した。
- #003の追加バースト：飛行・ポップ・波紋との同時演出を増やさないため追加しない。
- #007：#071を優先し、個数を二重に動かさない。
- #053/#052：ネイティブselect/detailsの操作を維持。独自の選択確定や自動閉鎖は加えない。
- #063：既存画面に＋/−個数ステッパーがないので追加しない。
- #158：既存ラベルを固定し、入力前後で位置を変えない。
- #061：サンプルは排他的な選択肢ではなく入力を置き換える操作なので、チェック状態は付けない。
- #159のモデルURLヒント：P3。既存のURL検証・説明を維持。
- 空き箱の線を描く動き、Aの選択ごとの回転、選択AIの光スイープ：同時演出を抑え、基本の入場・飛行と重ねない。
- #080の反映マーカーは背景の点滅を避け、不透明度変化に置換。安全文の文字自体は最初から読める。
- リセットは確認後すぐ空状態に戻す。削除を待たせるスタガーは加えない。
- #051：既存の非モーダルな開閉欄を維持するため、画面全面のオーバーレイや別のフォーカストラップは追加しない。
- P3（#094マーキー、#089ローディング、#216設計図背景、#050別ドロワー）は未実装。仕様書どおり先生の追加判断用とする。
- トーストが消えても、安全情報・コピー手順は既存の本文に残る。

## 追加文言の最終一覧

| 用途 | 文言 |
| --- | --- |
| 動き設定 | うごき / ON / OFF / OFF（端末設定） |
| モバイルの下バー | 自分の発明 N個 |
| 発明セットのハンドル | 発明セットを閉じる |
| ヒント01 | 夜、暗くなったら自動で光るライトを作りたい |
| ヒント05 | 暗くなったらライトがつく。明るくなったら消える |
| 入力補助 | ここに書くと、Gemが考えやすくなるよ / ✓ OK！ |
| コピー成功 | コピーしたよ！専用Gemに貼り付けて送信しよう |
| コピー失敗 | コピーできなかったよ。文章を選んでコピーしてね |
| サンプル | サンプルを読み込んだよ |
| リセット | リセットしたよ / やめる |
| 読み上げ完了表示 | 入力済み / コピー済み |
| AIの補足 | 説明 / B2S連携は未確認の説明 / Block2Scriptとのつながりは、まだ確認中です。先生と相談しよう。 |
| クレジット | 動きの名前と仕様は Motion Prompt（大滝昇平 / MIT）を参考にしています |

リセットの質問・確定ボタン、装置名・対応状況、端子・電源・Class・モデルURLに関する従来の文言は維持。追加のヒントは入力や保存値に混入しない。

## QAと再現コマンド

- `npm test`：既存ロジック21件と、導入前の空入力・防犯ライト・水やりスナップショット比較1件。空入力は生成禁止のまま、検証結果が一致。防犯ライトは従来同様、信号端子P1を指定して比較。
- `npm run test:browser`：既存の3スイートとモーション用スイート。入力・復元・コピー・Class保持・端子競合・ストレージ禁止・外部通信なしの回帰テスト。
- 新スイートで、ヒントと実値の分離、完了チェック、10回連打、飛行上限と後片付け、OFF保存、OS reduce優先、resetのEscと確定、コピー成功／失敗の演出分岐、キーボードの工程移動、360/768/1366pxの横はみ出しを検証。
- ChromiumでCPUを4倍遅くし、入力がその場で反映されることを検証。追加のフレーム測定では約57fps（最長フレーム51ms、Headless Chromium 156、4倍CPU負荷）を記録。測定結果は `work/motion-performance.json` に記録（測定環境限定、実機の30fps保証ではない）。
- スクリーンショットはgit対象外の `work/motion-*.png`。
- 実行時のJS追加は約27KB未満（minify前）。Canvasはコピー成功時に1枚だけ。WAAPIの稼働数に上限を設け、飛行は3枚まで。文字や明暗を高速で点滅させるアニメは作っていない。
- 背景は淡い色のみで、本文の濃い緑・白地の配色は維持。実機・スクリーンリーダーによる読み上げ順とコントラストの全要素測定は未実施。
- Firefoxの実行も試したが、この環境ではブラウザが「Could not find profile folder」で起動しない。WebKitはシステム依存ライブラリ不足で起動不可。最新版SafariとFirefoxの実機確認は未完了。Chromiumの結果をSafari検証済みとは扱わない。

追加検証は `MOTION_BROWSER=firefox node tests/motion.test.mjs` / `MOTION_BROWSER=webkit node tests/motion.test.mjs` で実行できる（対応するPlaywrightブラウザとOS依存ライブラリが必要）。
