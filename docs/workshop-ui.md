# 発明ワークショップ UI

## レイアウトと操作

画面は「左：作業メニュー」「中央：選択中の作業」「右：自分の発明」の3領域。左メニューはページ内の長いフォームへのスクロールではなく、中央の6パネルの表示を切り替えます。表示するパネルは常に1つです。前後の作業へ進むボタン、選択中メニューの強調、URLの `#step1`〜`#step6` も利用できます。

SのパネルにはSだけ、AにはAだけを表示します。画像カードで1台ずつ追加すると、右の装備欄に即座に反映され、中央には追加した装置1台の設定が開きます。設定を閉じると画像一覧を広く使えます。右の「編集」からは、その装置のステップと設定が開きます。同じ装置を複数使っても、それぞれの端子・メモを編集・削除できます。

右の装備欄にはS、A、AIの別カテゴリ、作品の目的と動作条件の概要を表示。欄の上部には3カテゴリの構成サマリーを固定表示し、詳細をスクロールしても組み合わせを確認できます。接続値は既存データの指定値と固定端子からのみ作ります。AIのClass名はJSON文字列として表示し、前後の空白、大小文字、行の区切りを失いません。装置名だけでも選択でき、キーボードではTab・Enter・Spaceが使えます。

## 状態・検証と互換性

`core.js`、`data/devices.js`、画像資産は変更していません。保存キー・version 1のデータ形式を維持し、作業中のパネルや編集中の装置はプロンプト用データに混ぜていません。

装備欄の必須入力と警告は毎回 `validate(state)` から取得します。端子重複、I2C共有、I2Cアドレス、AI、対応未確認の判定をUI側で再実装していません。「入力済み」は入力エラーがないという意味で、B2Sの動作保証ではありません。配線・対応の確認事項は別表示で残ります。最終チェックのエラーリンクを押すと、非表示パネルを開いて対象の設定へ移動します。

生成文・入力変更時のコピー無効化・コピー失敗時の手動選択・編集済み生成文・ローカル保存と復元・猫の給水サンプルは従来の処理を維持しています。外部送信、API、サーバー、データベースの追加はありません。

## レスポンシブと動き

- 1366pxなどの広い画面：左200px、残りを中央3：右2で配分。右の装備欄は固定追従し、内容が多い場合だけ内部スクロール。中央はページ本来のスクロールで操作します。
- 1024pxなどの中程度の画面：メニュー140pxに縮小し、中央と右を優先。
- 900px以下：メニューと中央を優先。装備欄は中央の上で開閉でき、装備欄から編集すると閉じて中央へ移動。
- 600px以下：メニュー、開閉式の装備欄、中央の1カラム。メニューは3列のコンパクトなボタン配置。

カードの浮き上がり・押下、中央パネルの切り替えはCSSで表現。追加時の小さな画像移動、装備カードの出現、装備欄の光はWeb Animations APIを使います。画面外の画像は飛ばさず、`prefers-reduced-motion: reduce` ではこれらの動きを止めます。追加ライブラリはありません。

## テスト・スクリーンショット

`npm test` は既存ロジック13件。`npm run test:browser` は従来のブラウザーテストと `tests/workshop.test.mjs` の両方を実行します。既存テストはメニューを経由する操作に移植し、画像・接続・コピー・保存・生成文などの検査は維持しています。GitHub Actionsも両方のブラウザーテストを実行します。

新しいテストは以下を検証します。

- 左の全6ステップ、中央が1パネルだけ表示されること、S/Aの非混在。
- 装備欄の即時更新、未設定から入力済みへの変化、端子競合と解消。
- 右からの編集・個別削除、同じ装置の追加、内蔵装置の端子不要。
- AIのClass名と生成文の一致、未確認機能の注意、旧保存形式からの復元。
- 最終チェックから非表示の装置設定を開く操作。
- 1366 / 1024 / 768 / 390pxの幅、3領域の位置関係、横はみ出し、装備欄開閉。
- キーボード操作、アニメーション抑制、外部リクエストとpageerrorがないこと。

画像はgit対象外 `work/workshop-1366.png`、`workshop-1024.png`、`workshop-768.png`、`workshop-390.png`、`workshop-mobile-equipment.png`、`workshop-prompt.png`、`workshop-reduced-motion.png` に保存します。

サブディレクトリ検証：`PORT=5181 BASE_PATH=/block2script-prompt-builder/ npm run dev` を起動し、`TEST_URL=http://127.0.0.1:5181/block2script-prompt-builder/ npm run test:browser` を実行します。

実Chromebookの性能・授業ネットワーク・支援技術での使用、micro:bit実機やGemの生成コードは別途確認が必要です。画像の出典とライセンスは [visual-ui.md](visual-ui.md) を参照してください。
